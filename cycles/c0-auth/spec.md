# C0 · 账号与权限体系 · 需求规格

> 版本 **v0.2** · 2026-11-07
> 状态：**待评审**（通过后才进入设计）
> v0.1 → v0.2 变化：明确 **openid 是唯一登录身份，手机号非必绑**；新增「手机号缺失强提醒」与「未开通页展示 openid」

---

## 一、一句话目标

让「**谁能登录、登录后能看到什么**」这套规则真正可用：

> 老师用自己的微信登录，只看到自己名下的学员；
> 老板登录看到全部，并能不停服务器就给新老师开号、给离职老师停号。

**否证条件**：如果老师账号能看到别人的学员，或开一个新号必须改代码/重启服务，本周期失败。

---

## 二、为什么是这件事

| 事实 | 后果 |
| --- | --- |
| 现在 `SecurityConfig` 只放行 `/api/health`，其余一律 401 | **任何业务接口都调不了**，C1 无从开始 |
| C1 的核心规则是「老师只看已核实且归属自己的学员」 | 没有身份与角色，这条规则无处落地 |
| 已发生过三次员工离职（曼曼 / 艺帆 / 璇子） | 账号必须能停用，**且历史记录不能跟着消失** |
| `app_user` / `app_role` / `app_user_role` / `app_staff` 已在 V001 建好 | 本周期只补**运行逻辑**，不重建结构 |

---

## 三、用户与角色

| 角色 | 人 | 能做什么 | 数据范围 |
| --- | --- | --- | --- |
| `owner` | 老板 | 全部功能 + 账号管理 | ALL（全部数据） |
| `teacher` | 柒柒、三水 | 业务功能 | SELF（只看自己名下） |
| `operator` | —（预留） | C0 不实现具体权限 | — |

**一个人可以有多角色**（`app_user_role` 是多对多），本周期不阻止，默认每人一个。

---

## 四、核心流程

### 4.1 登录（openid 是唯一身份）

```
小程序 wx.login
   → code
   → POST /api/auth/login {code}
   → 后端调微信 code2Session（appid + secret）
   → 拿到 openid
   → 查 app_user（openid + status=ACTIVE）
        ├─ 没有或已停用 → 403，返回 openid 供页面展示
        └─ 有 → 查角色 → 签 JWT（7 天）
   → 返回 {token, user:{id,name,roles,staffId}, needMobile:true|false}
```

**没有密码、没有注册。** openid 是唯一凭证。

### 4.2 鉴权

```
请求带 Authorization: Bearer <token>
   → 解析 JWT → 取 userId
   → 查库确认 status=ACTIVE（★ 不信任 token 里的状态）
   → 注入 user + roles
   → 按路径与角色判断
```

**每次请求查一次库**：3 个用户，一次主键查询成本可忽略；换来**停用立即生效**。

### 4.3 数据范围

| 角色 | 规则 |
| --- | --- |
| `owner` | 不加过滤 |
| `teacher` | 按 `app_user.staff_id` 对应 `app_staff.id`，只看归属自己的记录 |

实现约定：数据范围判断只写在一处（`DataScopeService`），业务代码调用它，不各自拼 SQL。

### 4.4 账号开通（openid 从哪来）

**问题**：openid 是一串乱码，老师不知道怎么告诉你。

**解法**：小程序「未开通页」直接展示自己的 openid，并支持一键复制。

```
老师首次登录 → 403 → 未开通页
   → 页面显示：「你的微信号还没开通，把下面这串发给老板」
   → 显示 openid（可长按/点按钮复制）
   → 老师微信发给老板
   → 老板在后台开通：admin.ps1 create -OpenId <这串> -StaffName 柒柒 -Role teacher
   → 老师重新进入小程序 → 登录成功
```

这是本周期唯一需要人工搬运的一步，**3 个人，一次性的**。

### 4.5 手机号：非必填，但缺了要强提醒

**手机号不参与登录，只用于员工资料与联系。**

| 情况 | 行为 |
| --- | --- |
| 员工资料里有手机号 | 正常使用，不提示 |
| 员工资料里没有手机号 | 登录返回 `needMobile: true`；小程序每次启动**弹强提醒**，直到补上 |
| 补充方式 | ① 微信手机号一键授权（需 AppSecret）② 手工输入（兜底） |

**「强提醒」的边界**：弹窗，但允许「以后再说」——不能因为没手机号就挡住他用。它是一张每次都弹的提示卡，不是硬门槛。

## 五、规则

| # | 规则 |
| --- | --- |
| 1 | `openid` 唯一；一个 openid 只能对应一个 `app_user` |
| 2 | `mobile` 存在 `app_staff` 上，**可空**，不参与登录 |
| 3 | `app_staff.mobile` 为空 → 登录返回 `needMobile=true`，前端强提醒 |
| 4 | JWT 有效期 7 天；过期后小程序静默重新 `wx.login` |
| 5 | 未登录 → **401**；已登录但角色不够 → **403**；越权访问他人数据 → **404** |
| 6 | 账号停用后，已发出的 token **立即失效**（靠每次查库） |
| 7 | 日志里不出现 openid 全串（脱敏为前 4 后 4） |

## 六、接口清单（5 个）

| 接口 | 谁用 | 作用 |
| --- | --- | --- |
| `POST /api/auth/login` | 所有人 | code → token；未开通时返回 openid 供展示 |
| `GET /api/auth/me` | 所有人 | 当前用户 + 角色 + `needMobile` |
| `GET /api/admin/users` | owner | 账号列表（含是否有手机号） |
| `POST /api/admin/users` | owner | 开通账号（openid + 员工 + 角色） |
| `PATCH /api/admin/users/{id}` | owner | 停用 / 启用 / 改角色 |

**不做** `logout` 接口——token 在客户端，删掉即可。

## 七、小程序侧

| 页面 | 内容 |
| --- | --- |
| 启动逻辑 | 有 token 先 `/auth/me` 校验；无或失效 → 静默 `wx.login` |
| **未开通页** | 「你的微信号还没开通」+ **openid 展示与复制按钮** + 「发给老板」提示 |
| **手机号提醒** | 员工无手机号时，每次启动弹提示卡：一键授权 / 稍后再说 |
| 我的页 | 姓名、角色、手机号（有则显示脱敏，无则显示「去补充」）、退出登录 |

## 八、非目标（C0 一件都不做）

- ❌ 密码登录 / 找回密码 / 自助注册
- ❌ 手机号硬绑定（登录不依赖手机号）
- ❌ 细粒度权限点（按钮级、菜单级）
- ❌ 组织架构、部门、多门店
- ❌ 操作审计日志
- ❌ 小程序管理界面（用命令行管理账号）
- ❌ 员工资料维护界面（C0 用脚本初始化，后续周期再做）

## 九、Definition of Done

| # | 验收 | 怎么证明 |
| --- | --- | --- |
| 1 | 未开通的微信登录 → 403，且**返回 openid** | 用不在库里的 openid 调登录，检查响应体 |
| 2 | 开通后同一 openid 登录成功 | 返回 token + 姓名 + 角色 |
| 3 | teacher 只看自己 | 用 teacher token 访问 owner 接口 → 403 |
| 4 | 停用立即生效 | 停用后拿旧 token 请求 → **401** |
| 5 | 开号不用改代码/重启 | 通过 admin 脚本创建，随即能登录 |
| 6 | 未登录一律 401 统一 JSON | 任意接口不带 token |
| 7 | **员工无手机号时 needMobile=true 且前端强提醒** | 把某位员工的 mobile 置空，登录看响应与页面 |
| 8 | 冒烟脚本覆盖登录链路 | `ops/smoke.ps1` 新增用例，本地与线上都跑通 |

## 十一、依赖与风险

| 项 | 说明 |
| --- | --- |
| 依赖 AppSecret | 登录与手机号授权都要它；**没有就用 mock，链路照样能验完** |
| 依赖小程序域名 | 只有真机/体验版需要；开发者工具用 localhost 不受影响 |
| 风险：手工搬 openid | 3 个人一次性可接受；人数多了要改成「申请-审批」流 |
| 风险：手机号被忽略 | 强提醒若可无限「稍后再说」，可能永远不填 → C1 做消课时再加硬约束 |
