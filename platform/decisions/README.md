# ADR · 架构决策记录

> 记录「**为什么这么定**」，不记录「怎么做」。怎么做看 `platform/docs/`。
>
> 用途：半年后你会忘了当初为什么选 MyBatis、为什么不用 Redis。
> 没有 ADR，就会反复重新讨论，或者更糟——在不知情的情况下推翻它。

---

## 什么时候写

满足任一条就写：

- 选型（框架、库、协议）
- 放弃某个方案（尤其是「看起来更专业」的那个）
- 定了一条以后不好改的规矩
- 因为现实约束（内存、时间、人手）做了妥协

**不写**：代码怎么写、某个 bug 怎么修、日常操作步骤。

---

## 文件命名

`NNNN-短标题.md`，四位序号，从 0001 开始。

---

## 模板

```markdown
# NNNN · 标题

- 日期：YYYY-MM-DD
- 状态：采纳 / 已废弃 / 被 NNNN 取代

## 背景

当时面对什么问题，有哪些硬约束（内存、时间、人手）。

## 决策

我们决定做什么。

## 备选方案

| 方案 | 为什么不选 |
| --- | --- |
| A | ... |
| B | ... |

## 后果

- 好处
- 代价（诚实写，这条最重要）
- 什么情况下应该推翻它
```
