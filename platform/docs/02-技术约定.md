## 二、分层职责（违反即返工）

```
Controller   只做：参数校验、调 Service、包装响应。不许写业务。
Service      业务规则全在这一层。状态流转只在这里发生。
Mapper       只做 SQL。不许写业务判断。
```

**判断标准**：如果一段逻辑，换一个入口调用也要一样，它就该在 Service。

## 三、响应与错误码

统一响应：

```json
{ "code": 0, "msg": "", "data": {} }
```

| code | 场景 | 前端行为 |
| --- | --- | --- |
| 0 | 成功 | — |
| 400 | 参数不合法 | 提示，不重试 |
| 401 | 未登录 / token 失效 | 静默重登 |
| 403 | 无权限（openid 不在白名单、角色不够） | 提示，不重试 |
| 404 | 记录不存在**或无权访问** | 返回上一页 |
| 409 | 快照已更新 | 提示刷新 |
| 500 | 未预期异常 | 通用提示，日志留 traceId |

**两条硬规则**：

1. 异常绝不把堆栈、SQL、类名返回给前端
2. 越权访问统一返回 **404 而不是 403**——403 会泄露「这条记录存在」

## 四、数据库约定

1. **改表只能通过 `db/migrations/VNNN__描述.sql`**，不修改已提交的迁移文件
2. 表名前缀 = 模块名（`followup_snapshot`）；平台级表用 `app_` 前缀（C0 起：`app_user`、`app_role`）
3. 主键统一 `BIGINT AUTO_INCREMENT`，不用 UUID
4. 时间统一 `DATETIME`，应用层用 `Asia/Shanghai`
5. 金额统一 `DECIMAL(12,2)`
6. 手机号存全号（服务端需要），**但所有出口必须脱敏**

## 五、日志与脱敏

| 内容 | 打不打 |
| --- | --- |
| 路径、状态码、耗时、traceId、userId | ✅ |
| 请求体 / 响应体 | ❌ |
| 完整手机号 | ❌ 日志、异常消息、toast 全部禁止 |
| SQL 参数（prod） | ❌ |

**脱敏只有一份实现**：`common/MaskUtil.mask()`，其他任何地方不许再写正则。

## 六、测试：只测三处

| 测什么 | 为什么 |
| --- | --- |
| 脱敏 | 错了直接泄露隐私 |
| 状态继承 / 流转 | 错了会把已核过的人重新变成待核，或反过来 |
| 权限 | 错了老师能看到别人的学员 |

**其余不写单测。** 两周内不可能全覆盖，假装覆盖比不覆盖更糟。

## 七、配置与密钥

- appid / secret / 数据库密码 / JWT 密钥：**只走环境变量**
- 服务器上放在 `/opt/hearth/app.env` 与 `db.env`（权限 600）
- 仓库里只允许出现 `.env.example`，且值必须是 `<占位符>`
- 本地开发用 `application-local.yml`（已 gitignore）

## 八、性能预算（这台机器很小）

| 项 | 预算 |
| --- | --- |
| 堆内存 | `-Xmx320m` |
| 进程 RSS | < 600 MB |
| 连接池 | max 5 / min 1 |
| 接口响应 | P95 < 300ms |
| 并发 | 峰值 < 10 QPS（3 个用户） |

**内存吃紧时优先压自己的堆，绝不动 MySQL 的全局参数**——同机还跑着小智。
