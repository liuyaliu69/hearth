# 04 · 发布与运维

> 版本 v1.0 · 2026-11-06
> 这份文件回答：**怎么安全地把东西放到线上，出事了怎么退。**
> 每一条都是踩过或差点踩的，不要绕过。
>
> 具体操作步骤（nginx 片段、systemd 单元、首次上线、内存观察）见 [`06-ECS部署手册.md`](06-ECS部署手册.md)。

## 一、环境矩阵

| 组件 | 本地 | 线上 |
| --- | --- | --- |
| 后端 | `localhost:8080` | ECS `127.0.0.1:8080` |
| 入口 | 本地 nginx `localhost:8081/hearth/` | `https://www.huohuawd.cn/hearth/` |
| 数据库 | 本地 MySQL 8.4，库 `hearth` | ECS MySQL，库 `hearth` |
| JDK | 24（**编译仍 `release=21`**） | OpenJDK 21 |
| 日志 | `ops/nginx/logs`、控制台 | `journalctl -u hearth` |

**两种环境下后端收到的路径完全一致**（都是 `/api/...`），nginx 只负责剥掉 `/hearth/` 前缀。

## 二、发布八步（`ops/deploy.ps1` 实现）

| # | 步骤 | 失败时 |
| --- | --- | --- |
| 1 | 预检：工作区干净、mvn/java/ssh/密钥就绪 | 退出 |
| 2 | 构建：`mvn clean package -DskipTests`（`release=21`） | 退出 |
| 3 | 本地冒烟：`localhost:8081/hearth/api/health` | **退出，线上纹丝不动** |
| 4 | 上传：scp 到 `/opt/hearth/app.jar.new`（不覆盖正在跑的） | 退出 |
| 5 | 切换：原子 `mv` + `systemctl restart hearth` | 自动回滚 |
| 6 | 三验：systemd active → 本机 8080 → 外网 `/hearth/` | 自动回滚 |
| 7 | 报告：写 `ops/releases/<版本>.md` + 追加 `CHANGELOG.md` | — |
| 8 | 留底：保留 `app.jar.prev` 一个版本 | — |

**为什么构建在本地**：服务器可用内存约 1350 MB，跑 Maven 会直接挤掉 MySQL 和小智。这是硬约束。

## 三、三层验证（缺一层都会出现「我以为好了」）

| 层 | 命令 | 含义 |
| --- | --- | --- |
| 1 进程 | `systemctl is-active hearth` | 服务活着 |
| 2 服务 | `curl 127.0.0.1:8080/api/health` | 应用能响应 |
| 3 外网 | `curl https://www.huohuawd.cn/hearth/api/health` | nginx + 证书 + 域名都对 |

**只有三层全绿才算发布成功。**

## 四、回滚

```bash
ssh root@101.200.14.51 '
  cp /opt/hearth/app.jar.prev /opt/hearth/app.jar
  systemctl restart hearth
  sleep 8
  systemctl is-active hearth
'
```

**数据库回滚不做**（Flyway 社区版无 undo）。改表出问题的兜底是**发布前备份 + 恢复**，
所以第五节的备份必须先于任何 schema 变更执行。

---

## 五、备份与恢复

```bash
# 每日 03:10 备份，保留 7 天
mysqldump --single-transaction hearth | gzip > /var/backups/hearth/hearth-$(date +%F).sql.gz
find /var/backups/hearth -name '*.sql.gz' -mtime +7 -delete

# 恢复
gunzip -c /var/backups/hearth/hearth-YYYY-MM-DD.sql.gz | mysql hearth
```

**恢复演练必须真做一次**，不是只把脚本写出来。没恢复过的备份不算备份。

## 六、上线前差异检查（本地绿 ≠ 线上绿）

| # | 差异点 | 怎么验 |
| --- | --- | --- |
| 1 | JDK 21 vs 24 | JAR 用 `release=21` 编译；启动不报 `UnsupportedClassVersionError` |
| 2 | nginx 前缀剥离 | `curl https://www.huohuawd.cn/hearth/api/health` |
| 3 | 环境变量 | `/opt/hearth/db.env`、`app.env` 存在且 600 |
| 4 | 小程序合法域名 | 只有体验版真机才校验；开发者工具不会 |

---

## 七、排障速查

| 现象 | 先查 |
| --- | --- |
| 外网 502 | `systemctl status hearth`、`journalctl -u hearth -n 50` |
| 外网 404 | nginx location 是否被改动、`proxy_pass` 末尾斜杠是否还在 |
| 启动即退出 | 环境变量缺失、数据库连不上（看 stderr） |
| 内存告警 | `free -m`、`ps -eo comm,rss --sort=-rss \| head -5` |
| 小智站点 502 | **首要怀疑是我们挤爆了内存**，先降 `-Xmx` |

---

## 八、禁止操作

- ❌ 在服务器上跑 `mvn`（内存不够）
- ❌ 动 `/api` 与 `/` 的 nginx location（那是小智的）
- ❌ 改 MySQL 全局参数（会拖慢同机另一个站点）
- ❌ 不停服直接覆盖 jar（必须原子替换）
- ❌ 不带备份就改 schema
- ❌ **在没验证替代副本前删除任何目录**（2026-11-06 事故）
