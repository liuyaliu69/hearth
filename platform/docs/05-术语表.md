# 05 · 术语表

> 版本 v1.0 · 2026-11-06
> 这份文件回答：**一个词只准有一个意思。**
> 越往后模块越多，同一个概念被叫成三个名字，是最常见的退化方式。

---

## 一、业务术语（followup 模块）

| 术语 | 英文/代号 | 定义 | **不要叫** |
| --- | --- | --- | --- |
| **快照** | snapshot | 某一天从三体导出的跟进总表副本，一天一份 | 导出、数据、名单 |
| **疑点** | flag / reason | 系统按规则自动标记「这条数据可能有问题」 | 异常、警告、错误 |
| **疑点规则** | reason_code | 具体哪一条规则被命中，如 `MOBILE_BAD` | 校验、检查项 |
| **核实** | review | 老板逐条确认数据可用：确认 / 修正 / 排除 / 挂起 | 审核、审批 |
| **待核实** | PENDING | 默认状态，未核过 | 未处理、待办 |
| **已核实** | VERIFIED | 核过且可用，可以分发 | 已通过、已确认 |
| **排除** | REJECTED | 这个人不用跟，不进分发 | 删除、作废 |
| **挂起** | PARKED | 现在判断不了，以后再说；不分发 | 搁置、暂缓、延后 |
| **分发** | dispatch | 把已核实的人送进老师视野 | 分配、派发、下发 |
| **继承** | inherit | 新快照沿用上期核实结果（关键字段没变时） | 沿用、复用 |
| **队列** | queue | 老师端的优先级分组：临期 / 沉默 / 囤课 / 未转化 | 分类、标签 |
| **临期** | RED | 时间卡剩余天数 0–30，**最高优先级** | 到期、即将过期 |
| **积压** | pending backlog | 待核实的总条数，常驻显示 | 待办数、剩余 |

## 二、平台与账号术语（C0 起）

| 术语 | 英文/代号 | 定义 | **不要叫** |
| --- | --- | --- | --- |
| **用户** | `app_user` | 能登录平台的人，绑定一个微信 openid | 账号、成员 |
| **员工** | staff | 业务实体（老师/前台），**可以离职**，不等于用户 | 用户、人员 |
| **角色** | `app_role` | 一组权限的身份标签，如 owner / teacher | 职位、身份 |
| **数据范围** | data_scope | 角色能看多少数据：`ALL` 全部 / `SELF` 只看自己名下 | 权限（口语易混） |
| **权限点** | permission | 一个具体功能，如 `followup:review` | 菜单、按钮 |

> **用户 ≠ 员工**：员工是业务实体，离职后历史记录仍归属他；用户是登录账号，离职即停用。
> 两者分开，才能回答「这个老师走了，他的学员怎么转」。

## 三、工程术语（跨模块）

| 术语 | 定义 | 备注 |
| --- | --- | --- |
| **平台** | 这个仓库 / 这个 Spring Boot 应用 | 不是「系统」「项目」 |
| **模块** | 平台里的一块业务，如 `followup` | 不是「功能」「子应用」 |
| **周期** | 一次有明确起止和验收的开发轮次（P0 / C0 / C1） | 不是「迭代」「版本」 |
| **版本** | 周期发布时打的号（v0.1.0 / v1.0.0） | 一个周期一个版本 |
| **地基** | 跨周期复用的一切：结构、约定、脚本、流程 | 不是「基础设施」（那个指服务器） |
| **探针** | `/api/health` 这类只为验证链路而存在的接口 | 不是「健康检查」（口语可用） |
| **冒烟** | 发布前后自动跑的一组最小验证 | 不是「测试」（测试指单测） |
| **原子替换** | 先把新 jar 传成 `.new`，再 `mv` 覆盖，避免读到半个文件 | — |

## 四、明确不用的词

这些词一旦出现，说明有人在重新发明概念，应当停下来对齐：

| 别用 | 因为 |
| --- | --- |
| 「客户」指学员 | 学员就叫学员；客户指付钱的家长/本人，容易混 |
| 「订单」指跟进记录 | 订单是钱，跟进是话 |
| 「任务」指核实项 | 核实就叫核实；任务指老师端待办 |
| 「同步」指「更新」 | 同步意味着双向，我们只有单向导出 |
| 「智能」「AI 驱动」出现在功能命名里 | 说了等于没说，且会过时 |

## 五、维护规则

1. 新概念**先加进这张表，再写代码**
2. 同一个概念在两个地方叫法不同时，**以本表为准**
3. 每个周期结束时回看一次：有没有新词没进表
